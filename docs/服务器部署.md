# 青盾服务器部署

服务器 SSH 别名：`pingpop-prod`，地址 `62.234.114.47`，用户 `ubuntu`。
使用本机 `~/.ssh/config` 中已有部署密钥，不保存 SSH 密码。

网站入口：<https://lexpilot.mizki.online>，使用独立 HTTPS 证书并自动续期。原有其他站点保持运行。
网站按用户要求公开访问，无全站密码弹窗。新版使用独立访客 Cookie 隔离事项、材料、报告与备份；公开模型调用使用服务器配置的 API 余额。以下描述须在部署新版后生效。
保留 Nginx 接口限速和跨站来源校验。原访问凭据文件已不用于网站认证。

## 访客记录与旧数据

- 首次访问自动创建访客身份，无需注册。HTTPS 下使用 `__Host-qingdun_visitor` Cookie，设置 Secure、HttpOnly、SameSite=Strict，有效期一年；数据库仅记录身份的哈希值。
- 每个事项的归属独立保存在 `case_owners` 表，所有事项接口（包括附件、OCR、报告、备份、重置）在处理前校验归属。恢复备份会生成属于当前访客的新副本，备份不能指定归属。
- 升级前的无归属事项与原文件继续留在共享数据目录，但不会自动分配给第一个访客，也不会对公众列出。需要找回旧个人材料时，由服务器管理者离线备份、核实归属后迁移，不使用公开认领入口。
- 访客身份不支持跨设备同步。清除 Cookie、使用无痕模式或更换设备可能无法找回，请在事项报告中下载完整备份并妥善保管。
- `DATA_DIR` 可指定独立数据目录，供测试使用；生产默认继续使用发布目录中指向共享数据的 `data` 链接。

## 后续更新

在本项目对 Codex 说“部署最新版本到服务器”，执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy.ps1
```

脚本运行测试、构建、打包代码，通过 SSH 上传，以新版本目录启动服务并检查健康状态。
仅包含 `server/`、`dist/`、依赖清单和发布脚本，不上传本地事项、材料、日志、密钥或 Windows 的 node_modules。
生产 API Key 在首次部署时单独上传，后续更新保留服务器配置。

## 服务器文件

- `/opt/qingdun/current`：当前版本的符号链接。
- `/opt/qingdun/releases/`：历史代码版本。
- `/opt/qingdun/shared/.env`：API Key、模型与网站地址，权限 600。
- `/opt/qingdun/shared/data/`：数据库与上传材料，更新不覆盖。
- `/opt/qingdun/shared/backups/`：每次更新前的 SQLite 一致性快照；原始材料保留于共享目录。
- `/opt/qingdun-runtime/node/`：独立 Node 24 运行环境。
- `/etc/systemd/system/qingdun.service`：开机自启和崩溃重启。
- `/etc/nginx/sites-available/lexpilot`：域名的 HTTPS 反向代理、请求限速和 HTTP 证书验证路径。
- `/etc/nginx/sites-available/qingdun`：限速区域定义及旧 8083 地址跳转。

服务日志：`sudo journalctl -u qingdun -n 100 --no-pager`。
重启：`sudo systemctl restart qingdun`。
修改 API Key 后需重启服务。API Key 不进入前端或发布包。

若要在新电脑部署，需要先配置 SSH 密钥并经服务器管理员授权。
网站使用默认 HTTPS 443 端口，HTTP 80 自动跳转 HTTPS。旧的 pingpop.mizki.online:8083 自动跳转新域名。
证书由 certbot.timer 自动续期，续期后执行 Nginx 检查并重载。
